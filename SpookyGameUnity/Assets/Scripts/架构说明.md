# 游戏架构说明

## 📦 核心服务（由 Bootstrap 初始化）

### Bootstrap.cs
- **作用**：游戏唯一入口，负责初始化所有服务
- **位置**：
  - 主菜单场景：`MainMenu > Bootstrap`
  - 游戏场景：`Scene_0 > Shared > Bootstrap`
- **初始化顺序**：
  1. EventBus（事件总线）
  2. SceneService（场景管理）
  3. FlagService（旗标管理）
  4. InputService（输入服务）

### EventBus.cs
- **作用**：全局事件中枢，用于解耦通信
- **使用方式**：
  ```csharp
  // 发布事件
  EventBus.Publish(new GameStateChangedEvent(GameState.Exploring));
  
  // 订阅事件
  EventBus.Subscribe<GameStateChangedEvent>(OnGameStateChanged);
  ```

### SceneService.cs
- **作用**：管理场景加载和关卡切换
- **核心功能**：
  - `LoadScene(sceneName, callback)`：加载场景
  - `ActivateStage(stageId)`：激活指定关卡（无转场）
  - `FadeToStage(stageId, intertitle, duration)`：带转场效果切换关卡

### FlagService.cs
- **作用**：管理全局布尔旗标（如道具、门状态等）
- **使用方式**：
  ```csharp
  // 设置旗标
  FlagService.SetFlag("has_key", true);
  
  // 获取旗标
  bool hasKey = FlagService.GetFlag("has_key");
  ```

### InputService.cs
- **作用**：输入服务初始化（点击式游戏模式）
- **说明**：实际输入处理由 `Interactor.cs` 负责

## 🎮 游戏逻辑组件

### Interactor.cs
- **作用**：处理鼠标悬停和点击交互
- **位置**：`Scene_0 > Shared > Interactor`
- **功能**：
  - 检测鼠标悬停的 `Interactable` 对象
  - 处理点击交互
  - 显示/隐藏交互提示
  - 切换鼠标光标

### Interactable.cs（抽象类）
- **作用**：所有可交互物体的基类
- **使用方式**：继承并实现 `OnInteract(GameObject actor)`
- **示例**：`Say.cs`（点击后显示文本）

## 🖼️ UI 组件

### MainMenu.cs
- **作用**：主菜单 UI 逻辑
- **位置**：主菜单场景
- **功能**：
  - 开始新游戏
  - 继续游戏（预留存档系统）
  - 设置
  - 退出

### PromptUI.cs
- **作用**：显示交互提示（如"点击查看"）
- **位置**：`Scene_0 > Shared > UI_Root > PromptUI`

### FadeScreen.cs
- **作用**：黑幕转场效果和标题显示
- **位置**：所有场景都需要

### PauseMenu.cs
- **作用**：暂停菜单（功能已移除，保留接口）

### WinScreen.cs
- **作用**：通关界面

## 🗂️ 配置系统

### GameConfig.asset（ScriptableObject）
- **作用**：集中管理所有游戏配置
- **位置**：`Assets/Resources/GameConfig.asset`
- **配置项**：
  - 场景名称
  - 关卡配置（ID、标题、初始旗标）
  - 转场设置
  - 游戏设置

## 🚫 已移除/不需要的组件

### ❌ GameManager.cs（已删除）
- **原因**：所有功能已由其他组件负责
  - 服务初始化 → `Bootstrap.cs`
  - 输入处理 → `Interactor.cs`
  - 游戏状态 → `EventBus` + `FlagService`

### ❌ PlayerController.cs（已删除）
- **原因**：点击式游戏不需要角色移动

### ❌ SaveService.cs（已删除）
- **原因**：暂不需要存档系统

## 🔄 游戏流程

### 启动流程
```
1. Unity 启动 MainMenu 场景
2. Bootstrap.Awake()
   └─ 初始化所有服务
3. Bootstrap.Start()
   └─ 检测当前场景类型
       ├─ 如果是主菜单 → 淡出黑幕，显示主菜单
       └─ 如果是游戏场景 → 激活首个关卡
```

### 场景切换流程
```
1. 玩家点击"开始游戏"按钮
2. MainMenu.OnStartGameClicked()
   ├─ 清除旗标
   └─ SceneService.LoadScene("Scene_0")
3. 场景加载完成回调
   └─ SceneService.FadeToStage("D1", "DAY 1 · 第一天")
4. FadeToStageCoroutine
   ├─ 黑幕淡入（隐藏当前场景）
   ├─ 显示 Intertitle 标题
   ├─ ActivateStage("D1")  ← 激活关卡
   ├─ 隐藏 Intertitle
   └─ 黑幕淡出（显示新关卡）
```

### 关卡切换流程
```
1. 玩家触发关卡切换条件（如点击门）
2. 调用 SceneService.FadeToStage("D2", "DAY 2 · 第二天")
3. FadeToStageCoroutine
   ├─ 黑幕淡入
   ├─ 显示标题
   ├─ 禁用所有关卡（Stage_D1, Stage_D2, ...）
   ├─ 启用目标关卡（Stage_D2）
   ├─ 应用初始旗标
   ├─ 隐藏标题
   └─ 黑幕淡出
```

## 📝 开发规范

### 1. 服务使用规范
- ✅ **直接调用静态方法**：
  ```csharp
  FlagService.SetFlag("door_open", true);
  SceneService.ActivateStage("D2");
  ```
- ❌ **不要尝试获取实例**：
  ```csharp
  // 错误示例
  FlagService flagService = FindObjectOfType<FlagService>();
  ```

### 2. 事件订阅规范
- ✅ **在 OnEnable/OnDisable 中订阅/取消订阅**：
  ```csharp
  private void OnEnable()
  {
      EventBus.Subscribe<GameStateChangedEvent>(OnGameStateChanged);
  }
  
  private void OnDisable()
  {
      EventBus.Unsubscribe<GameStateChangedEvent>(OnGameStateChanged);
  }
  ```

### 3. 场景配置规范
- ✅ **所有场景必须有 Bootstrap**
- ✅ **Bootstrap 必须引用 GameConfig**
- ✅ **关卡根节点命名必须为 `Stage_[ID]`**（如 `Stage_D1`）
- ✅ **关卡根节点初始状态必须禁用**

### 4. 配置管理规范
- ✅ **所有配置集中在 GameConfig.asset**
- ❌ **不要在代码中硬编码场景名、关卡ID**

## 🎯 常见问题

### Q: 为什么删除了 GameManager？
**A**: 因为它的所有功能都有更好的替代方案：
- 服务初始化 → `Bootstrap`
- 输入更新 → `Interactor` 自己的 `Update()`
- 状态管理 → `EventBus` + `FlagService`

### Q: InputService 还有用吗？
**A**: 有用，但只负责初始化。实际的输入处理在 `Interactor.cs` 中。

### Q: 如何添加新关卡？
**A**: 
1. 在游戏场景中创建 `Stage_[ID]` 根节点
2. 在 `GameConfig.asset` 的 `Stages` 数组中添加配置
3. 初始状态设为禁用

### Q: 如何在代码中切换关卡？
**A**: 
```csharp
// 方法 1: 直接切换（无转场）
SceneService.ActivateStage("D2");

// 方法 2: 带转场效果（推荐）
StageConfig stage = gameConfig.GetStageConfig("D2");
SceneService.FadeToStage("D2", stage.intertitle, gameConfig.defaultFadeDuration);
```

## 🎓 总结

**核心思想**：
- **服务化**：核心功能封装为静态服务，全局访问
- **事件驱动**：通过 EventBus 解耦组件通信
- **数据驱动**：通过 ScriptableObject 集中管理配置
- **单一职责**：每个组件只负责一件事

**不需要的东西**：
- ❌ GameManager（功能重复）
- ❌ PlayerController（点击式游戏）
- ❌ SaveService（暂不需要）

现在你的架构是**精简、高效、易维护**的！🚀
